# v16-coverage 虚拟试衣评测交接文档

## 1. 项目简介

`v16-coverage` 是一个独立交付的虚拟试衣评测器，目录位置：

```text
workspaces/tryon-eval/deliver/v16-coverage/
```

它不依赖外层 `evaluation-retrieval-agent` 仓库运行。评分配方、VLM judge 启动逻辑、评审 Web app 都在本目录内，任意 `python3 >= 3.9` 环境即可启动。

当前交付的评测方法是：

```text
hybrid-editscope-zoomgate-122b-v16-coverage-1read
```

README 中记录的验证效果：

- agreement：90.9%
- precision：0.818
- recall：0.847
- accuracy：0.908

评测目标是对每张虚拟试衣生成图输出：

```text
PASS / NOT PASS + reason
```

核心 judge 是 `Qwen3.5-122B-A10B`。评测器会检查生成图相对于输入服装和输入模特的保真情况，包括服装细节、模特姿态/身份、非目标区域是否被误改、视觉质量等。


## 2. 目录结构

```text
run.py                    单一入口，负责 venv bootstrap、judge 启动/复用、评分和报告生成
config.yaml               数据集配置，定义输入图、输出图、sample 匹配规则和 method
setup.sh                  一键创建本包自己的 .venv
requirements.txt          核心依赖：FastAPI、uvicorn、numpy、Pillow、PyYAML
requirements-metrics.txt  可选指标依赖：torch、torchvision、timm
scorer/                   byte-frozen 评分配方和 vLLM judge launcher
evaluator/                GPU、verdict、review model 等辅助逻辑
webapp/                   可选 review Web app，FastAPI + 已构建静态前端
runs/<ts>/                每次运行的报告、jsonl、日志和 review 数据
README.md                 英文主说明
CLAUDE.md                 给 Claude Code 的运行约束和操作说明
```

重要原则：

- 不要从外层 ERA 仓库 import 任何代码。
- 不要随意修改 `scorer/_v16.py`、`scorer/_v15_reference.py`、`scorer/_editscope.py`、`scorer/_ntmetric.py`、`scorer/_v13_eval/*`，这些是已校准的 byte-frozen scorer。
- `runs/` 是审计产物，不要重写已经生成的评分行。

## 3. 安装

进入交付包目录：

```bash
cd workspaces/tryon-eval/deliver/v16-coverage
```

创建本包自己的虚拟环境：

```bash
bash setup.sh
```

`setup.sh` 实际执行的是：

```bash
python3 run.py --bootstrap-only
```

它会创建：

```text
workspaces/tryon-eval/deliver/v16-coverage/.venv
```

这个 `.venv` 使用 `--system-site-packages`，所以系统里已有的 `torch`、`vllm`、`numpy` 等不会重复下载。安装完成后会写入 `.venv/.bootstrapped`，重复执行通常是快速 no-op。

如果只需要纯 VLM judge，不需要 report-only 指标依赖，可以用轻量安装：

```bash
bash setup.sh --light
```

即使没有提前执行 `setup.sh`，第一次运行 `python3 run.py ...` 也会自动 bootstrap 并重新进入 `.venv`。

## 4. 如何启动

### 4.1 检测数据集，不启动 GPU

先确认配置里的样本数量：

```bash
python3 run.py --detect-only
```

指定单个数据集：

```bash
python3 run.py --dataset job3a --detect-only
```

### 4.2 跑一个小样本 smoke test

每个 method 只跑前 3 个样本，不打开 Web app：

```bash
python3 run.py --dataset job3a --limit 3 --no-webapp
```

### 4.3 跑完整配置数据集

默认跑 `config.yaml` 中所有配置的数据集：

```bash
python3 run.py
```

只跑一个数据集：

```bash
python3 run.py --dataset job3a
```

无界面运行，只产出报告：

```bash
python3 run.py --dataset job3a --no-webapp
```

### 4.4 复用已启动的 judge

如果已有 OpenAI-compatible judge 在运行，优先复用，避免重复占 GPU：

```bash
python3 run.py --dataset job3a \
  --endpoint http://127.0.0.1:8011/v1 \
  --served Qwen3.5-122B-A10B \
  --no-webapp
```

### 4.5 指定模型路径

默认会自动扫描 `/dev/shm/models` 和 `/mnt/image-edit/models/Qwen/Qwen3.5-122B-A10B`。如需明确指定：

```bash
python3 run.py --dataset job3a \
  --model-path /mnt/image-edit/models/Qwen/Qwen3.5-122B-A10B
```

### 4.6 重新打开已完成 run 的 Review Web app

```bash
python3 run.py --review-only --run runs/<timestamp>
```

## 5. 主要功能

### 5.1 数据集读取

`run.py` 从 `config.yaml` 的 `data.datasets[]` 读取数据集定义。当前配置里已有：

- `ces_old`
- `whq_new`
- `job3a`

每个 dataset 主要字段：

- `dataset_id`：数据集名称，传给 `--dataset` 使用。
- `data_root`：数据根目录。
- `sample_glob`：从 method 路径下匹配 sample 的 glob。
- `sample_key`：样本 key 生成方式，例如 `relpath` 或 `basename`。
- `input_roles`：输入图文件名，例如 `input_cloth.png`、`input_model.png`。
- `methods[].method_id`：方法名。
- `methods[].path`：该方法的样本目录。
- `methods[].output_file`：生成图文件名。

如果要评测新的数据集，优先改 `config.yaml` 中对应 dataset 的 `methods[].path`、`output_file`、`input_roles` 和 `sample_glob`。

### 5.2 VLM judge 启动或连接

没有传 `--endpoint` 时，`run.py` 会尝试启动本地 vLLM judge，默认端口：

```text
8741
```

传入 `--endpoint` 时，不启动新 judge，而是连接已有服务。

### 5.3 评分逻辑

每个样本会走 byte-frozen 的 `score_v16_coverage` 配方：

- reference-anchored edit-scope spine：检查非目标区域是否被误改。
- consolidated coverage read：一次 judge 调用覆盖服装保真、模特保真、视觉质量。
- report-only CPU 指标：target-region color/DINO 等只作为佐证，不决定 PASS/NOT PASS。

最终由 judge 的 fused `defect` 标志得到 verdict：

- 无 defect：`PASS`
- 有 defect：`NOT PASS`

原因会用自然语言写入报告，例如：

- `edit-scope: a non-target region changed`
- `target garment not faithfully reproduced`
- `color changed`

### 5.4 报告生成

每次运行都会写入：

```text
runs/<TIMESTAMP>/
```

关键产物：

- `REPORT.md`：主要人工可读报告，包含 method pass-rate 汇总和逐样本结果。
- `verdicts.jsonl`：机器可读结果，每行一个 verdict。
- `results/full/<combination_id>/scores.<dataset_id>.jsonl`：原始 scorer 输出。
- `human/review_model.json`：供 Web app 展示。
- `detection.json`：数据集检测信息。
- `logs/`：运行日志。

逐样本评分失败会写成 `ERROR` 行，不会伪造 PASS 或 NOT PASS。

### 5.5 Review Web app

默认完整运行结束后会尝试打开 review Web app。Web app 是辅助检查界面，主要交付仍然是：

```text
runs/<TIMESTAMP>/REPORT.md
```

如果只需要报告，使用：

```bash
python3 run.py --no-webapp
```

## 7. 常用参数

| 参数 | 作用 |
| --- | --- |
| `--dataset {ces_old,whq_new,job3a,all}` | 指定要评测的数据集，默认 `all` |
| `--limit N` | 每个 method 只跑前 N 个样本，用于 smoke test |
| `--detect-only` | 只打印样本数量，不启动 GPU |
| `--endpoint URL` | 连接已有 OpenAI-compatible judge |
| `--served NAME` | 指定 endpoint 上的模型名 |
| `--port N` | 启动本地 vLLM judge 时使用的端口，默认 8741 |
| `--model-path PATH` | 指定 judge 权重目录 |
| `--light` | 跳过 torch/timm 指标依赖，纯 VLM 判断 |
| `--no-webapp` | 只生成报告，不打开 review Web app |
| `--review-only --run runs/<ts>` | 对已有 run 重新打开 review Web app |
| `--bootstrap-only` | 只创建 venv 和安装依赖 |

## 8. 运行环境和资源注意事项

### 8.1 GPU

默认本地启动 judge 时需要 4 张空闲 H100，单卡约 70GB 显存。启动前建议检查：

```bash
nvidia-smi
```

不要在未检查 GPU 的情况下并发启动多个 vLLM judge。

### 8.2 GPU watchdog

环境中可能有 `NoGPUAlarmNew.py` watchdog。`run.py` 会在启动 vLLM 前尝试停止它，并在运行结束后恢复。

如果自动处理失败，可以手动执行后重试：

```bash
sudo pkill -9 -f "python3 -u NoGPUAlarmNew.py"
```

### 8.3 模型路径

默认模型路径优先自动扫描。常用路径：

```text
/mnt/image-edit/models/Qwen/Qwen3.5-122B-A10B
```

如果模型在 `/dev/shm/models/` 中，通常加载更快。使用 `--model-path` 可以显式指定。

### 8.4 指标依赖

DINOv2 / color-EMD 等指标在 CPU 上运行，并且只作为报告佐证，不决定最终 verdict。缺少这些依赖时会降级，不应影响 PASS / NOT PASS 的有效性。

## 9. 常见问题

### 9.1 `--detect-only` 样本数为 0

检查 `config.yaml`：

- `methods[].path` 是否存在。
- `sample_glob` 是否能匹配样本目录。
- `output_file` 是否存在于样本目录中。
- `input_roles` 中的 `input_model.png`、`input_cloth.png` 是否能按配置找到。

### 9.2 GPU 不足或 vLLM 启动失败

先看 `nvidia-smi`，确认至少 4 张 H100 空闲。若已有 judge 服务，优先用 `--endpoint` 复用。若 watchdog 占用 GPU，按上文手动 kill 后重试。

### 9.3 Web app 打不开

Web app 不是主要交付物。先确认 `REPORT.md` 和 `verdicts.jsonl` 是否已生成。如果只需要结果，用 `--no-webapp`。如需复查已完成 run：

```bash
python3 run.py --review-only --run runs/<timestamp>
```

### 9.4 评分过程中出现 ERROR 行

`ERROR` 表示该样本真实评分失败，系统不会伪造 verdict。应查看对应 run 的 `logs/`、`scores.<dataset_id>.jsonl` 和样本路径，确认是否是图片缺失、路径配置错误、judge 返回异常或 I/O 问题。

### 9.5 已经有 judge 在跑

不要再启动一个新的 judge。使用：

```bash
python3 run.py --endpoint http://127.0.0.1:<port>/v1 --served Qwen3.5-122B-A10B
```

## 10. 接手建议

接手后建议按这个顺序熟悉：

1. 阅读 `README.md`，确认交付包定位和输出格式。
2. 阅读 `CLAUDE.md`，了解 Claude Code 接到“evaluate”请求时应如何映射到 `run.py`。
3. 运行 `python3 run.py --help`，确认当前 CLI 参数。
4. 运行 `python3 run.py --detect-only`，确认数据集配置可读。
5. 对 `job3a` 跑 `--limit 3 --no-webapp`，看 `runs/<ts>/REPORT.md` 格式。
6. 需要评测新数据时，只改 `config.yaml` 的 dataset/method 路径和文件名，不动 byte-frozen scorer。
