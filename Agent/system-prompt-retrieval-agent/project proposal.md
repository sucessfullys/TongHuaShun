System Prompt and Negative Prompt Retrieval Agent for Image Generation and Editing

1. Project Motivation

This project aims to build a System Prompt and Negative Prompt Retrieval Agent for image generation and image editing workflows.

The current focus is a specific but representative task: finding suitable prompts for a clothing-transfer / virtual try-on pipeline. In this workflow, Gemma-4-31B-it first generates an intermediate editing prompt, and Flux2Klein then uses this intermediate prompt, the input images, and a negative prompt to generate the final clothing-transfer image.

The main search target is no longer only the system prompt. The agent should retrieve and evaluate two types of prompts:

1. System Prompt Candidate
   → Controls how Gemma-4-31B-it understands the task and generates the intermediate editing prompt.
2. Negative Prompt Candidate
   → Controls what Flux2Klein should avoid when generating the final transferred image.

Negative prompts are commonly used in diffusion-based image generation to specify unwanted visual elements, artifacts, or failure patterns that the model should avoid. They can help suppress undesired details, although finding effective negative prompts can be non-trivial and model-dependent.  ￼

The broader goal is to build a repeatable framework for prompt retrieval, testing, evaluation, and reuse in multimodal generation/editing pipelines. The first version will focus on clothing transfer, and later versions may extend to other image editing tasks.

2. Current Target Task

The updated initial pipeline can be described as:

[System Prompt Candidate + Fixed User Input]
        ↓
Gemma-4-31B-it
        ↓
Intermediate Editing Prompt
        ↓
[Intermediate Prompt + Model Image + Clothing Image + Negative Prompt Candidate]
        ↓
Flux2Klein
        ↓
Transferred Image

The key question becomes:

Given a fixed user input format, how can we find a better combination of system prompt and negative prompt so that Gemma produces a reliable intermediate prompt and Flux2Klein generates a better clothing-transfer result?

The system prompt mainly affects the intermediate prompt produced by Gemma. It should help Gemma:

- translate the user instruction into English
- identify clothing types in both images
- decide whether the task is upper-body replacement, lower-body replacement, full-outfit replacement, or outerwear addition
- generate a concise replacement statement
- avoid unnecessary detailed clothing descriptions

The negative prompt mainly affects the final image generated by Flux2Klein. It may help reduce common failure cases such as:

- distorted body shape
- incorrect clothing region replacement
- duplicated garments
- unwanted accessories
- texture artifacts
- blurry or low-quality details
- changed face or identity
- changed background
- inconsistent lighting
- extra limbs or malformed hands

The project should treat both prompt types as searchable components. In the early version, they can be searched independently or in simple combinations. Later, the agent may learn which system prompt and negative prompt work well together.

3. Project Structure

The project will be divided into three stages. At this proposal stage, each stage is only described at a high level. More detailed implementation plans will be written separately.

⸻

Stage 1: Remote Model Deployment

The first stage prepares the remote model environment.

The goal is to make the necessary models available on the 3H100 server, so that the local agent can call them through stable ports or APIs.

The expected deployed models include:

Flux2Klein
Gemma-4-31B-it
Qwen3-VL-8B-Instruct

Their rough roles are:

Gemma-4-31B-it
→ Generates the intermediate editing prompt under a candidate system prompt.
Flux2Klein
→ Produces the final clothing-transfer image using the intermediate prompt, input images, and candidate negative prompt.
Qwen3-VL-8B-Instruct
→ Provides possible visual evaluation or intermediate analysis signals.

This stage should mainly focus on making the remote inference pipeline usable and stable. It does not need to solve the full prompt-search problem yet.

The detailed server configuration, deployment commands, model paths, ports, request format, and testing procedure will be specified later in the V0.1 plan.

⸻

Stage 2: Local Agent and Prompt Search Workflow

The second stage builds the core local agent.

The goal is to design a workflow that can test different system prompt candidates and negative prompt candidates under the same fixed input setting.

At a general level, the agent should be able to:

- manage system prompt candidates
- manage negative prompt candidates
- call the remote Gemma model
- collect Gemma-generated intermediate prompts
- call the remote Flux2Klein image editing model
- collect generated transferred images
- call or prepare evaluation tools
- save experiment records
- compare different system prompt / negative prompt combinations

The prompt search can start from a simple structure:

System Prompt Search
→ Find prompts that make Gemma generate clearer and more correct intermediate editing prompts.
Negative Prompt Search
→ Find prompts that help Flux2Klein avoid common artifacts and preservation failures.
Joint Prompt Comparison
→ Compare combinations of system prompts and negative prompts based on the final image quality.

The evaluation does not need to be overly complicated in the first version. A practical starting point is to separately inspect:

Intermediate Prompt Evaluation:
- whether the intermediate prompt is clear and concise
- whether the clothing replacement logic is correct
- whether the garment type is specific enough
- whether the prompt avoids unnecessary detail
Final Image Evaluation:
- whether the final image follows the intended clothing-transfer instruction
- whether the target clothing is correctly transferred
- whether the model identity, pose, and background are reasonably preserved
- whether the negative prompt helps reduce artifacts or unwanted changes

The detailed agent architecture, tool interfaces, prompt candidate generation method, negative prompt candidate strategy, evaluation schema, logging format, and search strategy will be specified later in the V0.2 plan.

⸻

Stage 3: WebUI for Result Display

The third stage builds a simple WebUI for inspecting and comparing results.

The goal is not to build a complex product interface at the beginning. The main purpose is to make the prompt-search process easier to review, debug, and present.

The WebUI may display:

- input model image
- input clothing image
- user instruction
- system prompt candidate
- negative prompt candidate
- Gemma-generated intermediate prompt
- Flux2Klein output image
- evaluation result or comments
- prompt version history

This interface should help the developer or reviewer quickly understand:

- which system prompt works better
- which negative prompt works better
- which system prompt / negative prompt combination works better
- whether a failure comes from Gemma, Flux2Klein, the negative prompt, or the evaluation step
- which prompt rules are useful
- which prompt rules may be too rigid or unnecessary

The detailed UI layout, backend connection, result storage format, and interaction design will be specified later in the V0.3 plan.

⸻

4. Expected Output of the System

At this stage, the expected output should remain practical and lightweight.

The system is expected to produce:

- a set of tested system prompt candidates
- a set of tested negative prompt candidates
- generated intermediate prompts from Gemma
- final clothing-transfer images from Flux2Klein
- basic evaluation records
- comparison results between prompt candidates
- comparison results between negative prompt candidates
- comparison results between system prompt / negative prompt combinations
- saved logs for later analysis

The system may also gradually accumulate reusable knowledge, such as:

- useful system prompt rules for clothing replacement
- useful negative prompt patterns for clothing-transfer artifacts
- common failure cases
- examples of strong and weak system prompts
- examples of strong and weak negative prompts
- evaluation comments for different output types
- prompt fragments that can be reused in later tasks

The first version does not need to guarantee that it finds the globally best system prompt or negative prompt. A more realistic goal is to build a repeatable workflow that can help identify better prompt combinations than manual trial-and-error.

⸻

5. Short Project Positioning

This project builds a local agent framework for retrieving, testing, and refining system prompts and negative prompts in multimodal image editing workflows.

The first use case focuses on clothing transfer. Given a fixed multimodal input format, the agent searches for:

1. a system prompt that helps Gemma-4-31B-it generate a concise and accurate intermediate editing prompt;
2. a negative prompt that helps Flux2Klein reduce artifacts and unwanted visual changes.

The project will be developed in three stages:

V0.1: Remote model deployment
V0.2: Local agent and prompt-search workflow
V0.3: WebUI for result display

Each stage will have its own detailed plan later.
